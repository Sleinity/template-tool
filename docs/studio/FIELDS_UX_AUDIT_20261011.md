# Fields UI and workflow audit — 2026-10-11

The highest-impact improvement is trustworthy context: show the design that contains the field, validate the complete draft before enabling Apply, and make shared versus design-specific effects clear. Keep the existing functions and SDK authorities. A compact inspector is appropriate; a new authoring model or renderer redesign is not supported by this audit.

This is an audit, not a UI implementation. Saved user configurations were not applied, reordered, or deleted.

## Scope and evidence

Reviewed current Carrousel saved-template Settings → Fields on `127.0.0.1:5173`, and the previously created three-export audit Family on an isolated `5184` origin. Inspected all seven field types, all five choice-type editors, Advanced field and option details, Family scope/inheritance, reorder flyout, filters, preview controls, Apply/Discard and the navigation guard. Source identity is commit `944c51b33433ce2e37ec05f7de66457d5154d5b4` **plus the dirty worktree**, identified by the [source and screenshot hashes](evidence/fields-ux-audit-20261011/record.json).

The [previous whole-app audit](UI_UX_AUDIT_20261011.md), [implemented UI refinements](UI_REFINEMENTS_20261011.md), and [Choices implementation](../architecture/field-choices-implementation.md) provide context. Previously fixed issues are not counted again: Choices uses a switch, Advanced is compact, counts are unbadged, filters occupy their row, the redundant result count is removed, and preview zoom has a box.

Evidence classifications:

- **Live:** personally observed this run, with reversible local drafts discarded.
- **Source:** current implementation supports the finding; the specific outcome was not exercised.
- **Historical:** earlier tests/audit, not a fresh pass.
- **Hypothesis:** proposed usability consequence requiring a task study or targeted test.

The measured single-page viewport was 1257 × 1475 CSS pixels. An attempted viewport override did not change that page's measured width; the resulting image is named `fields-1257.jpg`, not narrow evidence. Browser-native calendar/color popovers, screen-reader announcements and constrained-width interaction were not certified. This was a development build, without production timing measurements.

Priorities: **P1** misleading task context or substantial correctness risk; **P2** recurrent friction, validation or accessibility problems; **P3** lower-impact polish. No P0 outage/data-loss finding was reproduced.

## Recommended coherent flow

1. **Scan:** compact labels, meaningful effective summaries, field type and only actionable status. Keep reorder reachable without opening configuration.
2. **Open:** retain one inline inspector and a correctly labelled matching preview. Distinguish editing scope from inspection design.
3. **Configure:** Label, Rules/Format and optional Choices. Keep imported defaults and affected designs available at the point of conflict. Hide integration metadata from the routine path.
4. **Correct:** keep partial drafts local; one useful error beside its control, one concise summary when needed. Apply requires the complete candidate to pass current SDK validation.
5. **Accept:** Apply changes the accepted session; Discard restores only the unapplied form. Show the durable save status separately and lead to Review.
6. **Leave:** valid draft offers Apply and continue / Discard / Keep editing; invalid draft offers correction or discard. Preserve focus, entered data, resource ownership and recovery behavior.
