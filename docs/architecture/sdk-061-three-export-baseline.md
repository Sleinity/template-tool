Both `sdk-061-three-20261004-a` and `sdk-061-three-20261004-b` completed two captures on each of Validate, Fields, editor, and PNG for all three ZIPs. Stable captures are evidence of reproducibility, not source fidelity.

The active [profile](../../fidelity/gates/sdk-061.json) and [run-bound disposition](../../fidelity/gates/sdk-061-dispositions.json) are tracked. The latter is bound to run `sdk-061-three-20261004-b` and records a cause, candidate hash, rationale, and regeneration command for every fixture and surface. Candidate PNGs and binary packets remain local ignored artifacts under `fidelity/candidates/`; `node scripts/fidelity/reference-review.mjs sdk-061-three-20261004-b` generated local, source-linked packets for all 12 surfaces under `fidelity/evidence/reference-review-sdk-061-three-20261004-b/`. The former ten-ZIP profile and disposition are preserved in `fidelity/gates/archive/`; its Family failures do not block this baseline. Historical fixtures and references remain in the registry.

The current blockers are specific:

1. **Cover visual output is not source-faithful.** Its exact embedded preview fades the hand/image into the dark footer and shows an open right arrow. The current PNG has a hard image edge and a boxed-looking arrow. The source visual node `987:6774` declares an ordered `SOLID` + `IMAGE` + `GRADIENT_LINEAR` stack with `DARKEN` on the gradient; the arrow node `987:6779` points to an SVG asset containing the expected open path. This narrows investigation, but does not by itself prove one runtime root cause. A fixture-led mixed-paint/vector diagnosis is required. No renderer behavior or approved reference was changed here.
2. **Carrousel's imported Color precision was corrected after these historical runs.** Run `sdk-061-three-20261004-b` recorded source RGB `(0.8999999761581421, 0.699999988079071, 1)` being quantized to `(0.8980392156862745, 0.6980392156862745, 1)` on initial materialization and Reset. Core now retains the exact marked SOLID paint when the sparse imported default represents it. The public three-export host check compares the ZIP `template.json`, normalized base, initial materialization, and Reset after save/reload by exact numeric equality. Explicit edits and intentionally different V2 defaults still write canonical RGB to the bound index. This removes the source-value blocker; it does not approve a renderer reference or resolve Cover.
3. **All three source-sized PNGs differ from their embedded previews, and none has an approved renderer reference.** A pixel with any RGB-channel delta greater than 10 occurs in 1.782% of Now Hiring, 5.543% of Cover, and 1.709% of Carrousel pixels. These measurements are triage evidence only. Now Hiring text/image differences and remaining Carrousel differences still need source-level disposition. All 12 renderer surfaces, three scene candidates, and 12 settlement bundles remain unapproved; no guarded promotion was performed. Carrousel's observational settlement reports `pending-measurements`, while Now Hiring and Cover report `ready`. This distinction does not weaken the visual gate.

Stored source previews and PNG-export candidates were inspected in this run. The other three surface captures are complete and stable, but their individual source-fidelity reviews are pending. This is **stored-capture review**, not a claim of live interactive Studio review. No source preview was substituted for an approved renderer reference.

## Next architecture contract after this gate

The next milestone remains **internal compiler-result consolidation**, with no production-session switch in this gate. The minimum result should be a discriminated internal single/Family import outcome containing: the exact loaded source and provenance; ordered, validated canonical V2 package sources; source preview and source metadata; layered importer/asset/font diagnostics; explicitly owned temporary resources with release/transfer semantics; and, for Family assembly, variant IDs/order plus the existing selector/configuration result. It must retain invalid outcomes without normalizing them into success. It should reuse `buildZipPackageImportResult` and `createTemplateFieldFamilyFromSourcesV2` rather than decode the ZIP twice or recreate field semantics. Renderer evidence, accepted content, and session revisions stay outside the compiler result.

Differential tests should compile each of the three exact ZIPs through the current public path and the proposed internal adapter, then compare canonical package/source provenance, preview hash, field bindings/defaults, diagnostics, asset descriptors, ownership cleanup, and failed-import outcomes structurally. A separate Family test can exercise current public assembly independently; it does not enter this three-export release gate. Existing single and Family sessions, materializers, persistence, renderer packages, and save/export semantics must remain authoritative and unchanged until equivalence is proven.
