# Internal compiler-result equivalence gate

## Audit and scope

Baseline: `sdk-061-mask-settlement-final-20261007a` reports GO for the exact
Now Hiring, Cover and Carrousel sources. The active profile records exact ZIP,
template.json and preview hashes; its source-authoritative environment records
the verified Geist Mono, Inter Tight, Funnel Display and Rethink Sans binaries.
See [the three-export baseline](sdk-061-three-export-baseline.md).

Core owns ZIP/source decoding, V1 source reading, V1-to-V2 normalization and
strict canonical validation. Browser's `buildZipPackageImportResult` owns asset
ingestion, managed-font linking, optional enrichment, diagnostics, source
metadata, the already decoded preview Blob and default-store temporary URLs.
`parseTemplatePackageV2` then produces the V2 canonical result.
`createTemplateFieldFamilyFromSourcesV2` clones supplied V2 packages, preserves
source configurations through common fields and atomic overrides, and validates
every variant. It does not reread ZIPs. Studio additionally applies authoring
policy; that policy does not enter this adapter.

## Contract

The contract remains internal to template-browser. Its single-source path is now
consumed by the supported V2 import facade described below; Family composition
remains test-only. Ordered,
read-only source views retain every existing import data property and complete
V2 parse result, including optional presence, raw loader/provenance, diagnostics,
preview, defaults, bindings, assets, fonts and exact numerical paints.
Resource callbacks are private to explicit handles, not data fields. Native
Blob/reader resources stay opaque; no duplicate ZIP byte envelope is introduced.
Views are compile-time read-only; constructors freeze the envelope, not shared
native/source objects. Adapters never mutate their input authorities.

Single and Family outputs remain discriminated and use existing canonical
types. Ready requires existing import acceptance, valid import validation and
valid V2 parsing. This is not renderer/font/export readiness. Blocked outputs
retain available source/parse data; errors retain stage and original cause
separately from diagnostics. No partial Family assembly occurs. Caller source
IDs are preserved, empty/duplicate IDs are contract errors, and positional
mapping retains the Family authority's original generated identities.

## Ownership

Each source handle owns the existing import release callback. A Family retains
its source handles, including blocked/error outcomes; releasing either owner
cannot release a still-live peer. Source handles cannot be reused after their
own release. Release is idempotent and attempts every cleanup even if one fails.
Existing sessions retain managed URLs during load. Default stores release only
after the final compiler owner; session URL leases still protect live assets.
Caller-provided stores remain externally owned. Import exceptions keep pipeline
cleanup; normalization/assembly exceptions leave acquired resources releasable.
No new global URL registry or font activation policy is added.

## Limits and next handoff

Only the supported V2 import facade and test/harness code consume the internal
module. Family composition remains test-only. Read-only views retain
native/shared evidence; they are not a portable serialization or independently
editable snapshot. A released source's data remains inspectable, but its
temporary URLs cannot be assumed usable without another existing owner.
Configured external stores remain host-owned.

The first production consumer is documented below. A subsequent adoption must
continue proving the same authority/resource handoff and must not implicitly
unify sessions, migrate persistence, make this contract public, connect the two
architectural experiments, or change renderer/readiness semantics.
