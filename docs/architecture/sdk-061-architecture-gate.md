Four Family ZIPs fail canonical semantic validation before rendering. Their first field binds `appearance.fills` to a `RECTANGLE` mask source, which the current public importer rejects as `field.invalid-property`. The exact rejected node IDs are `800:142` (landscape gray), `800:67` (landscape pink), `800:166` (portrait gray), and `800:177` (portrait pink). The public-only Family gate reproduces the same diagnostic for all four, so selector assembly and standalone-versus-variant output equivalence cannot be certified. This is a source/exporter versus accepted-field-contract question, not a reason to weaken validation or rewrite the renderer in this milestone. Preserve these exact ZIPs and resolve the color/mask field contract in a separate fixture-led decision.

The standalone `exporter-061-carrousel` has the same `backgroundColor` field/property on a `RECTANGLE` (`987:6811`) but marks that node `isMask: false` and imports successfully. The four Family variants mark their corresponding color-field rectangle `isMask: true`. This comparison narrows the contract question to an editable color field on a mask input; it does not establish which side of that contract should change.

The six importable sources produced **48/48 complete, stable browser captures** (six ZIPs × four surfaces × two repetitions). The four rejected Family sources have **0/32** required captures. Their eight initial renderer references were promoted individually with source-specific reasons through `fidelity:update`, then `compare-existing` checked the same capture run against the newly approved files.
