# SDK 2.0.1 functional patch release

The human explicitly approved this release path and publication on 2026-10-19 after confirming that the field-rule fixes must not depend on a particular private template. The [existing full release workflow](../../.github/workflows/release.yml) excludes only `sdk-v2.0.1`; the [bounded patch workflow](../../.github/workflows/sdk-2-0-1-patch.yml) owns that tag. Other releases retain the exact-fixture certification gate. This is a functional regression release, not new Figma source-fidelity or pixel certification.

The patch guard compares against `sdk-v2.0.0`, rejects any API inventory change beyond version metadata and rejects Core/renderer runtime changes outside the reviewed native single/Family session and React field-session files. No public API, saved-record schema, migration, fixture, reference or tolerance changes are included.

Both workflow jobs deliberately point private fixture lookup at an absent runner directory, so accidental dependencies fail instead of borrowing local inputs. Studio setup uses `--without-source-fidelity` to run its portable journey; its original exact-ZIP/font journey remains the default outside this approved patch.

Before any publication, portable CI and the standard field-rule gate must pass, including all 50 architecture and 88 choice checkpoints, guarded textarea transactions, Studio drafts and setup. Sequential prepack produces one archive train. Supplied-archive npm and pnpm consumers exercise public ZIP admission, native editing/save/reopen, delivered TypeScript examples, font/readiness/PNG ownership and blocked storage. The external source-fidelity portion of the packed consumer is explicitly excluded only with `--without-source-fidelity`; strict source checks remain the default for existing certification callers. The actual npm archive publisher runs in dry-run mode without lifecycle scripts before publication.

A successful receipt binds the source commit, three archive hashes and every npm/pnpm host check. The protected tag-only job consumes that same artifact. It preflights every package and tag before publishing any package, publishes sequentially with lifecycle scripts disabled, checks registry SHA-512 integrity and retains all three package tags at the exact commit. Authentication or network errors never mean that a version is absent. Reruns may resume identical accepted bytes, never overwrite versions or move tags. Publication cannot be atomic across three registry packages; a failure stops subsequent mutations and leaves the GitHub release as a draft until a verified retry completes.

Downloaded registry tarballs must match the accepted archive SHA-256 values. Registry-derived delivery generation uses the shared inventory, verifies all links/checksums, repeats installed npm/pnpm host acceptance and verifies the published Core consumer. The draft receives the complete generated asset inventory before being made public with the short patch release notes. Existing published releases remain immutable.

The publisher concurrency follow-up from [SDK 2.0.0](sdk-release-automation.md) is addressed for this bounded path by publishing verified immutable archives. The older full-release Changesets path remains unchanged and retains its separately documented follow-up.

Acceptance reports are retained by the patch workflow and remain separate from source-fidelity evidence. The delivery manifest's packing status stays `not-yet-verified`; successful functional reports and registry byte verification supply their own scoped evidence.
